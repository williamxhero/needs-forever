## Problem Statement

没有确定的控制与持久化规则时，worker 提前收尾、重复通知或人工暂停都可能产生漏续跑、重复执行或错误唤醒。需要先证明监督程序能可靠处理一个任务，再接入真实 AI 判断。

本子 SPEC 为总 SPEC #19 的 S1，对应“阶段一：确定性闭环”。继承 #19 的目标、协议、状态与授权合同，不承诺整个 v0.1 已完成。

## Solution

实现可运行的前台 CLI、app-server 协议适配、单 worker 控制循环和持久状态，以固定结果的假 judge 驱动同线程续跑。用公开 CLI 行为验证提前结束、去重、稳定完成与暂停门禁，为 S2 提供真实判断的接入边界。

## User Stories

1. 作为任务负责人，我希望输入目标、验收和授权后启动一个明确工作区的任务，以便监督程序保存完整任务合同。
2. 作为任务负责人，我希望程序按实际 Codex 版本初始化协议连接，以便不用猜测接口字段。
3. 作为任务负责人，我希望阶段性交卷后继续原 worker 线程，以便已有上下文和产物保留。
4. 作为任务负责人，我希望连续两次提前结束都被处理，以便没有只续跑一次的隐藏限制。
5. 作为任务负责人，我希望重复和过期事件没有调度效果，以便同一回合不会触发第二个动作。
6. 作为任务负责人，我希望 Ctrl+C 先持久化暂停，以便迟到结果不能恢复任务或宣称完成。
7. 作为任务负责人，我希望查询状态时不运行模型，以便可以随时检查任务进展。
8. 作为任务负责人，我希望明确 resume 使用原线程和任务快照，以便不会接管其他会话。
9. 作为任务负责人，我希望已完成任务保持 DONE，以便重复通知和重启不重开旧任务。
10. 作为任务负责人，我希望日志区分消息已发送和回合已确认开始，以便知道是否真的推进。
11. 作为任务负责人，我希望同一任务只能有一个监督进程，以便多个写入者不会竞争状态。
12. 作为后续实现者，我希望假 judge 可替换为真实 judge，以便 S2 沿用同一个控制与发送入口。

## Implementation Decisions

- 使用 TypeScript＋Node.js，前台运行，提供总 SPEC 定义的 start、status、resume 与 Ctrl+C 行为。任务与状态使用总 SPEC 的 schema_version 1，不另建平行合同；默认总回合和时长限制为 null。
- 启动检查记录 Codex 版本、工作区和隔离配置；管理本地 app-server 子进程，完成 initialize／initialized、唯一请求 ID、响应匹配、worker 创建或明确 ID 恢复，以及回合开始与结束事件适配。
- 固定职责为协议适配、控制循环、规则、judge 接口和存储。事件归一化后进入确定性规则；所有续跑通过唯一 sendNext。假 judge 只用于本阶段验证，不能作为真实审核能力交付。
- 实现 ACTIVE、WAIT_EXTERNAL、PAUSED、DONE 及总 SPEC 定义的 phase。异步结果落地前核对 ACTIVE、task_version 和预期回合；同时覆盖正在审核与已处理回合去重。
- 保存完整任务、worker 身份、当前回合、审核回合、全部已处理 ID、待发送动作、判断结果、限制累计和时间信息。原子替换状态、追加事件日志并输出摘要，同一任务持有唯一锁。
- 发送前持久化 prepared 和 delivery_id，响应或匹配 turn/started 提供目标回合 ID 后才确认开工。对发送结果未知的情况保留未确认状态，不盲目重发；完整断线历史核对在 S3 验收。
- 人工暂停先持久化并使在途结果过期，再中断自有调用；明确恢复递增任务版本，DONE 不可重开。固定结果夹具覆盖等待和完成门禁，但不冒充 S2 的真实 DONE 判定或独立验收。
- 实现演进保持 S2、S3 可使用同一入口和状态合同；本阶段不足以支持的恢复场景明确标记未验证，不增加新的自动暂停次数上限。

## Testing Decisions

最高边界为公开 CLI → 模拟 app-server 传输与固定 judge → 可观察的状态、事件和续跑结果。仓库当前没有运行时代码或测试先例；新测试验证行为，不锁定私有调用顺序。

- [ ] T01 simulated：第一阶段结束后，同一 worker 确认开始下一轮。
- [ ] T02 simulated：连续两次提前结束都正确续跑。
- [ ] T05 simulated：固定有效完成结果稳定持久化 DONE，重复事件不重启。
- [ ] T07 simulated：处理中重复事件合并，已处理事件与旧版本结果无调度效果。
- [ ] T08 simulated：覆盖 worker、假 judge 和验收调用夹具在途暂停，迟到成功不覆盖 PAUSED。
- [ ] 核对 status 不启动模型、恢复使用明确 worker ID 与原任务快照、锁阻止重复监督进程、待发送动作先落盘再发送。
- [ ] 记录协议适配使用的实际 Codex 版本；假传输结果只标 simulated，不能标 live。

退出条件：上述行为验证通过，有可运行 CLI、状态与事件示例，并能以相同控制边界交给 S2。这里只完成 S1，不关闭总 SPEC。

## Out of Scope
