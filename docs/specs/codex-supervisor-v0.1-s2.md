## Problem Statement

假 judge 只能证明调度动作，不能判断用户目标是否完成、当前路线是否仍可推进。需要独立的真实判断与可校验完成证据，避免 worker 自报 blocked 或 DONE 就结束任务。

本子 SPEC 为总 SPEC #19 的 S2，对应“阶段二：真实判断”。依赖 S1 的确定性控制闭环，继承总规格全部授权和状态门禁。

## Solution

用每次新建的只读 judge 线程审核有界证据快照，严格返回 CONTINUE、DONE、WAIT_EXTERNAL。接入独立验收和受保护文件哈希，验收失败时把真实证据交回原 worker 修复；在公开 CLI 行为边界验证真实提前收尾、换路和最终完成。

## User Stories

1. 作为任务负责人，我希望 judge 保留原目标、验收和授权，以便不受 worker 收尾措辞误导。
2. 作为任务负责人，我希望每次判断有独立只读线程，以便审核不能修改项目来满足结论。
3. 作为任务负责人，我希望证据 ID 可回溯且输出可严格校验，以便未知引用或非法 JSON 不被接受。
4. 作为任务负责人，我希望未完成时收到一个具体下一步，以便调查、换路和推进其他事项都能继续。
5. 作为任务负责人，我希望 worker 自报 blocked 后判断其他路线，以便局部失败不冻结全部任务。
6. 作为任务负责人，我希望 DONE 必须覆盖全部验收项，以便部分完成不被当作目标达成。
7. 作为任务负责人，我希望独立验收失败后自动继续修复，以便不依赖模型自述。
8. 作为任务负责人，我希望验收脚本和命令受到保护，以便不能篡改完成标准。
9. 作为任务负责人，我希望 WAIT_EXTERNAL 证明必要外部条件和无其他可做事项，以便只有真实依赖才进入等待。
10. 作为任务负责人，我希望普通技术选择按已确认规则答复，以便减少重复询问。
11. 作为任务负责人，我希望权限和未知请求按协议拒绝或取消，以便不越权也不永久悬挂。
12. 作为任务负责人，我希望暂停后在途 judge 或成功验收失效，以便保留控制权。
13. 作为任务负责人，我希望报告提供实际线程和事件证据，以便真实闭环能被复核。

## Implementation Decisions

- 在 S1 的 judge 边界接入真实 app-server 线程；worker 空闲时才创建一个新 judge，使用只读沙箱，不加载外部 MCP/apps 或续跑插件。判断结束归档，保留 ID；清理失败不推翻有效结果。
- 快照包含原任务合同、当前计划与剩余事项、本轮回复、工具与变更证据、最近验收、最近两次指令及结果、重复失败提示，以及总规格定义的任务、线程、回合与快照标识。
- 按总 SPEC 的 24,000 字符默认预算保留关键失败、变更和验收；目标与验收不截掉，授权保留，缺失部分标明。信息不足继续补证据，不推导为 DONE 或 WAIT_EXTERNAL。
- 每次 turn/start 传 outputSchema，程序校验 action、reason、evidence_ids、next_message、external 的完整约束。拒绝未知证据、非法字段组合和额外文本；失败不默认完成。完整超时与失败退避由 S3 验证，不得留下并发 judge。
- CONTINUE 经唯一发送入口向原 worker 下发具体下一步。WAIT_EXTERNAL 必须有 missing、实际 attempted、why_no_other_work、resume_when 及证据；只有当前没有其他授权工作可做才等待，并撤销在途调度。
- DONE 除证据成立外，配置 verify 时必须按固定 argv 在 worker 沙箱执行独立验收。非零、超时或未授权修改 protected_files 都拒绝 DONE；验收前后比较启动基线哈希，要求恢复受保护文件，不通过替换脚本或命令制造成功。
- 请求分普通选择、凭据与权限：普通选择复用已有答案和默认，适用时才选第一个有效项；其他请求按真实预授权处理。拒绝操作后仍可换已授权路线；未知类型依协议取消，必要时有记录地中断，终止后诊断。judge 的此类请求不递归调用 judge。
- worker、judge、验收异步结果都沿用版本和 ACTIVE 门禁。Ctrl+C 取消自有调用；无法单独取消验收时关闭受管 app-server，迟到成功不能覆盖暂停。
- 提供三阶段小型演示和独立受保护验收，保留完整三阶段目标，只在测试任务中要求 worker 每次做一阶段即交卷。

## Testing Decisions

复用 S1 的公开 CLI 和可替换传输边界，增加真实 judge、验收子进程与真实 Codex 事件证据。只断言可见决定、后续回合、授权结果与验收产物，不用最终文件正确代替监督过程证据。

- [ ] T01、T02 live：真实 worker 提前结束一次及两次，均在同线程进入下一轮。
- [ ] T03 live：第一路线必然失败时，给出实质不同且可验证的下一步并完成。
- [ ] T04 live：judge 选择 DONE 但独立验收失败，程序拒绝完成并让 worker 修复。
- [ ] T05 live：全部目标与验收成立后持久化 DONE，重复结束事件不再开工。
- [ ] T06 simulated：真实缺失条件、已尝试路线和无其他可做事项完整，进入等待后不被迟到事件唤醒。
- [ ] T13 simulated：普通选项、拒绝权限、未知请求分别正确答复、拒绝或取消；judge 不递归判断。
- [ ] 验收文件在验收前或期间被改动都拒绝完成，固定 argv 不可由 AI 替换。
- [ ] 验收成功与暂停竞态保持 PAUSED；无效 JSON、未知证据、信息不足不能接受为 DONE。
- [ ] 逐项保存 live／simulated／not_run、Codex 版本、系统、命令、线程 ID、关键事件和验收输出。

退出条件：真实 T01–T05 有可追查事件与验收证据，判断和验收约束通过；剩余恢复及真实暂停由 S3 完成。真实条件缺失时明确 not_run，不关闭总规格。

## Out of Scope

完整断网退避、app-server 异常重建、发送结果未知的历史核对、周期漏事件补偿与最终全矩阵验收属于 S3。排除多 worker、自动权限扩大、全局配置修改、第二套驱动及真实业务仓库的无隔离试验。
