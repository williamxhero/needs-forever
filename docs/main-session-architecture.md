# Main-session supervision

New installed-plugin starts use `control_mode: main-session`. The Desktop chat A performs the task with its existing model, tools and approvals. B is a hidden independent Node process holding task and A leases; C is a fresh independent read-only judge using the existing decision schema and evidence gates. B never resumes A through its own app-server.

Native PreToolUse/PostToolUse correlate the installed start/resume command, workspace, tool-use ID and unpredictable receipt challenge. This includes `functions.exec` Code Mode strings. Environment session IDs are diagnostic only. Before binding, state stays PAUSED/RECOVERING with PENDING_NATIVE_HOOK; trust belongs to Codex Settings > Hooks. Node/CLI doctor checks cannot establish Desktop trust or effectiveness.

The sole continuation entrance is a synchronous native Stop. B captures its request, generation, contract and input epoch, creates C, and returns `decision: block` plus a concrete reason only while that same request remains valid. An ensuing matching PreToolUse/PostToolUse pair confirms actual A activity; a returned response is insufficient. Terminal judgments require cited current evidence; configured fixed verification and protected baseline checks must also pass before DONE.

Pause/Interrupt persists PAUSED and invalidates current ownership before canceling B-owned C/verification. New UserPromptSubmit increments an input epoch, clears pending directions, retains the latest redacted prompt as context, and invalidates previous-epoch proof. It leaves original acceptance and authorization binding. Judgment and verification use a private state copy and guarded checkpoint writes, so late results cannot replace newer state. Recoverable service errors use the existing visible 5/15/60/300-second backoff within the original Stop deadline. Service auth/quota errors produce RECOVERING, never an invented task WAIT_EXTERNAL.

Unknown delivery, host restart/exit, hook timeout or changed package requires explicit resume. A reachable B does not imply a live host. Resume retires a recoverable B through its authenticated handle, proves matching old owners absent with ESRCH, rotates the run/handle and native challenge, and retains A, artifacts, original verifier baseline and cumulative counters. It waits for a fresh Stop without replaying old directions. Newly observed Desktop turn IDs count once; repeated Stops in one turn do not count new turns. A host without turn IDs can prove at least one turn but cannot prove additional turns from Stop responses alone. Time limits include ACTIVE judgment/recovery time, checkpointed every 250 ms; a crash may lose the last interval. Turn limits block further CONTINUE while allowing judgment of the currently permitted turn.

Workspace registration uses one atomically written file per state under `.codex-supervisor/main-session-bindings/`; readers also accept the earlier shared index. Independent preparations cannot overwrite one another and create no shared crash-prone index lease. Old checkpoints with missing mode remain independent-worker tasks, including their original status/pause/resume semantics. Core CLI rejects main-session resume before legacy mutation.

Two native-host behaviors remain explicit release gates. Desktop 0.159 stdin does not provide a documented stable event ID; fixture `event_id` retransmissions and concurrent requests are fenced, but indistinguishable host re-execution of identical stdin cannot be claimed deduplicated. The controller intentionally does not deduplicate by session, turn or payload because true later same-turn Stops must work. Also, documentation does not establish whether an internally generated continuation prompt fires UserPromptSubmit. Every observed UserPromptSubmit currently takes input precedence; real Desktop acceptance must verify continuation confirmation in that chain. These limitations are not resolved by simulated test success.
