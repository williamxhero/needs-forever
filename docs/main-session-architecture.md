# Main-session supervision

New installed-plugin starts use `control_mode: main-session`. The Desktop chat A performs the task with its existing model, tools and approvals. B is a hidden independent Node process holding task and A leases; C is a fresh independent read-only judge using the existing decision schema and evidence gates. B never resumes A through its own app-server.

Native PreToolUse/PostToolUse correlate the installed start/resume command, workspace, tool-use ID and unpredictable receipt challenge. The opt-in recognizer accepts one literal `node`/`node.exe` invocation (absolute executable paths and PowerShell `&` are supported), the exact installed script path, and `start`/`prepare`/`resume` in the operation position with literal task/state flags. The same recognizer guards both pre-observation and post-receipt correlation. Read-only commands such as `rg start <script>`, echoed examples, comments, unrelated object strings and `if (false)` code do not create observations.

For `functions.exec` Code Mode, the supported entry is a top-level `await tools.exec_command({cmd: "...", ...literalOptions})`, optionally wrapped in `text(...)`, or `const result = await tools.exec_command(...); text(result);`. Quoted/unquoted object keys, single/double-quoted strings and comments are supported. Dynamic expressions, template strings, conditional/loop/function wrappers, compound shell commands and other ambiguous forms remain neutral and cannot bind. The start/prepare/resume receipt explains this limited grammar. If an actual preparation was run through an unsupported form, it remains pending; explicitly use the supported direct `resume --state FILE` command to obtain a new native receipt. No JavaScript or shell code is evaluated by this recognizer. Environment session IDs are diagnostic only. Before binding, state stays PAUSED/RECOVERING with PENDING_NATIVE_HOOK; trust belongs to Codex Settings > Hooks. Node/CLI doctor checks cannot establish Desktop trust or effectiveness.

The installed adapter remains neutral for sessions that have not explicitly started/resumed a task through the authorized control entry: ordinary lifecycle callbacks (including natural-language mentions and doctor/status tool calls) return `{}` without creating task artifacts or B/C. Foreign callbacks cannot mutate another pending task; a released DONE binding does not reopen. No lifecycle handler declares unconditional supervision statusMessage. In pinned 0.159, however, the host emits HookStarted for matching synchronous plugin handlers before invoking their script, so the plugin cannot guarantee zero global dispatch, zero Node startup or zero generic host hook UI. Removing statusMessage removes the plugin-specific premature supervision claim, not the host's own lifecycle machinery.

The sole continuation entrance is a synchronous native Stop. B captures its request, generation, contract and input epoch, creates C, and returns `decision: block` plus a concrete reason only while that same request remains valid. An ensuing matching PreToolUse/PostToolUse pair confirms actual A activity; a returned response is insufficient. Terminal judgments require cited current evidence; configured fixed verification and protected baseline checks must also pass before DONE.

Pause/Interrupt persists PAUSED and invalidates current ownership before canceling B-owned C/verification. New UserPromptSubmit increments an input epoch, clears pending directions, retains the latest redacted prompt as context, and invalidates previous-epoch proof. It leaves original acceptance and authorization binding. Judgment and verification use a private state copy and guarded checkpoint writes, so late results cannot replace newer state. Recoverable service errors use the existing visible 5/15/60/300-second backoff within the original Stop deadline. Service auth/quota errors produce RECOVERING, never an invented task WAIT_EXTERNAL.

Unknown delivery, host restart/exit, hook timeout or changed package requires explicit resume. A reachable B does not imply a live host. Resume retires a recoverable B through its authenticated handle, proves matching old owners absent with ESRCH, rotates the run/handle and native challenge, and retains A, artifacts, original verifier baseline and cumulative counters. It waits for a fresh Stop without replaying old directions. Newly observed Desktop turn IDs count once; repeated Stops in one turn do not count new turns. A host without turn IDs can prove at least one turn but cannot prove additional turns from Stop responses alone. Time limits include ACTIVE judgment/recovery time, checkpointed every 250 ms; a crash may lose the last interval. Turn limits block further CONTINUE while allowing judgment of the currently permitted turn.

Workspace registration uses one atomically written file per state under `.codex-supervisor/main-session-bindings/`; readers also accept the earlier shared index. Independent preparations cannot overwrite one another and create no shared crash-prone index lease. Old checkpoints with missing mode remain independent-worker tasks, including their original status/pause/resume semantics. Core CLI rejects main-session resume before legacy mutation.

Supported Desktop 0.159 uses each native handler process invocation as the Stop occurrence boundary. Its official dispatcher executes each synchronous handler once; the adapter generates one UUID in its IPC envelope, and B persists admission before starting C. The StopRequest uses that UUID. Concurrent or completed replays of an admitted occurrence return an explicit error and cannot start another C, deliver another direction or silently allow a duplicate hook to stop. Accepted identities survive new input, pause and resume. A new native invocation receives a fresh UUID even when session, turn and stdin are identical. This is adapter identity, not invented host metadata; there is no automatic transport replay after unknown delivery. A future host version that adds native handler reruns needs a separately verified adapter contract.

Exact official 0.159 source also records Stop block prompts directly in the existing turn loop, bypassing UserPromptSubmit (which dispatches only for TurnInput::UserInput). Therefore internal continuation is not classified from prompt wording. Source provenance and Windows suspended-spawn fallback details are recorded in `docs/evidence/spec33/ticket38/native-continuation-source-probe.md`. Actual Desktop T02/T03 continuation and user-input precedence still require live acceptance; source and simulated tests do not establish that the running Desktop loaded trusted candidate hooks.
